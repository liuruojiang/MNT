# V1.6 / V8.0 共用双源核验入口

这一入口实际读取 Tiingo EOD 和 Yahoo chart，独立保存原始响应，核对两套策略合计 22 只 ETF。它不导入策略，不读写正式策略缓存，不替换数据源、不修复行情、不生成交易指令，也不部署到 Poe。策略脚本与参数保持原样。

## 手动运行

在本仓库运行：

```powershell
python -B tools/audit_us_sources.py --tiingo-credential '现有 .tiingo-token.dpapi 的完整路径'
```

也可把现有加密文件的路径作为参数交给 `tools/run_us_source_audit.cmd`。参数是文件路径，**不得填写 API token**。加密文件继续使用原来的 Windows DPAPI 存储与用户身份；本工具不复制、不迁移凭证、不输出明文。

默认检查本仓库及同级的 `美股多头策略`；若项目移动，使用 `--workspace` 指定这两个目录的父目录。可从任意工作目录调用此脚本。默认产物写入本仓库已忽略的 `data/source_audit/<UTC时间_唯一编号>/`，可用 `--output` 修改。

每次实时运行新取数据，不覆盖或自动复用旧运行，也不读取旧策略缓存。每源失败后停止请求该源，其他源继续；401、403、429、网络错误和结构错误均不能从旧报告恢复为成功。完整一轮 44 次 Tiingo 请求（每只元数据和日线各一次），22 次 Yahoo 请求；账户额度不足会保留已完成结果并明确失败，避免逐个重复撞额度。

## 产物与状态

- `report.html`：覆盖、差异及最近公司行动冲突清单。
- `report.json`：每只 ETF 的逐日差异、比较值、分配和拆股、缺日列表、实际正式脚本哈希、核验代码哈希及各项目关联。
- `snapshot.json`、`raw/`：采集时间、无密钥 URL、HTTP 状态及原始响应 SHA256；含失败记录。原始响应仅作归档，不视为可供生产使用的数据。
- `projects.json`：这次使用的项目范围、参数无关的审计阈值和正式脚本 LF 哈希。脚本哈希不一致时，项目范围标记 `BLOCKED_SOURCE_SCOPE`，需先重新确认依赖清单。

`BLOCKED` 表示本工具不能接受该 ETF 数据，`REVIEW` 表示仍有差异待解释，`OBSERVED_MATCH` 只表示检查窗口内观测匹配。**任何一种状态均不自动晋级生产。** 当前 BTC 等必需输入还未完成核验，因此完整项目统一 `REVIEW_REQUIRED`，命令退出 2；不能以 shell 命令成功与否替代报告阅读。此工具尚未接入正式策略的阻断链，不宣称它已经阻断 Poe。

## 比较口径

从 2003-01-01 检查历史（晚上市资产使用 Tiingo 元数据的实际可用起点）；不声明覆盖更早历史。V1.6 公共样本晚于这一日期。V8.0 包含 B7.8 的 AGG 和历史代理 EFA，不只检查当前显示池。

Tiingo `open/high/low/close/volume/divCash` 是当日份额口径，Yahoo 历史 OHLC 和现金分配已按之后的拆股换算。工具在比较副本内按**之后**拆股累计因子调整 Tiingo OHLC、现金和股数成交量，拆股当日不重复处理；原始文件和任一家 `adjClose` 均不改变。对 Tiingo `3.000003` 与 Yahoo `3:1` 等比例表示误差使用 1e-5 相对容差。该换算是核验口径统一，不是策略复权补丁。

现金分配和拆股单独比较；Yahoo 资本利得单列人工复核，不能直接与 dividend 相加而重复计入。分配日还核对现金总回报和 Yahoo 因子算法是否可以解释收益差异；非分配日的额外因子变化、已修正上游的重复复权会被标记。统一的复权归一化常数不影响日收益，不计作错误。

原始开收价容差 1bp，复权日收益差异容差 1bp，现金分配容差 max(0.001美元, 0.1%)，同口径股数成交量相对差异阈值 1%。这些是**审计阈值，不是策略参数或误差可忽略的投资判断**。零成交量保留，不填充、不换算成成交额；源间成交量差异继续留待解释。

默认 `auto` 按纽约时区 21:00 后的保守可用边界剔除未确认当日，再从 Yahoo SPY 得到最近交易日，兼容夏令时。SPY 超过可用边界七个自然日视为异常。SPY 仅作为参考日历，**不能排除两源共同缺日或在七日内共同过期**，尚非独立交易所日历认证。实时指定 `--cutoff` 必须等于最近 SPY 确认日；历史复现用原有当时快照，避免当前 Yahoo 拆股基准与历史截断后的 Tiingo 基准混合。

```powershell
python -B tools/audit_us_sources.py --offline-snapshot '某次运行的完整目录' --output '新的输出父目录'
```

离线模式明确标注 `OFFLINE_REPLAY`，验证每份响应的哈希、成功状态和项目配置；保留原采集时间，不能冒充最新行情。重新分析不重复调用 API，也不修正既有证据。

## 当前未覆盖与后续次序

BTC 的 UTC 交易日、聚合范围和成交量需要独立认证；Wind 的 A 股指数/成交额、FRED 宏观指标也不在本轮 ETF 接受范围。万得凭证和既有长短区间 guard 未改动。未创建自动定时任务。

遇到冲突先用发行人/交易所分配表裁定，再保持原参数通过正式脚本重放信号和回测。本工具只生成调查清单，不能把两源不一致直接认定为某家出错，也不能把已在正式脚本修复的 KMLM 上游差异再次补到价格中。

KMLM 2022 年独立证据：[发行人分配表](https://kraneshares.com/resources/2022_kraneshares_cap_gain.pdf)。字段说明：[Tiingo EOD](https://www.tiingo.com/documentation/end-of-day)。
