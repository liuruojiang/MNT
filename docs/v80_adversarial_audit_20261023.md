## 三项确定缺陷

### F1 / P1：成交额缺失被解释为未触发，Sub-A 恢复正常仓位

**位置：**生产文件 `_fetch_cn_amount_with_fallback`（2321–2337）、`_consecutive_below_amount` / `_build_consecutive_below_amount_signal`（2263–2289）、`_load_suba_volume_signal`（2417–2419）。

成交额入口只检查有效记录数量与最后日期，不检查有效样本内的交易日连续性。内部 NaN 让滚动均线失效并比较成 False；整行缺失则压缩连续天数。由于抓取没有抛异常，结果仍标记 `combined_unresolved=False`，最新日期检查也通过。CSIndex 原始解析器会跳过缺少 `tradingValue` 的行，因此整行缺失具有上游可达路径。

**最小反例与影响：**中证2000末三日成交额 80/70/60，完整序列应触发清仓；只将倒数第二日置 NaN 或删除，就变为不触发。通过 `run_cn_strategy → _apply_suba_volume_overlay_policy(...allow_unresolved_suba_volume=False)` 的正式策略调用，完整数据末日仓位为 **0**，损坏数据为持有 `1.930955`、仓位 **1.0**，没有中止或未知状态。这是合成反例，并非报告今日真实仓位错误。

**修补建议：**

1. 按每个指数的实际发布日期、A股交易日历，检查所需均线及连续天数窗口内的金额完整性、有限正值和唯一日期。发布前不可用和发布后缺数必须分开。
2. 使用“触发／未触发／不可判定”三态。OR 规则若另一条完整分支已经触发，可确定触发；否则未知分支不得当作 False。
3. 正式绩效路径对不可判定中止；信号降级路径显示 UNKNOWN，并阻止展示为正常可执行仓位。不能未经计算就假定所有缺数情况都应清仓。
4. signal、live signal、params、live params 同步披露数据截止日、缺失状态及最终执行尺度。

**验收：**NaN、整行缺失、非有限值、重复日期均不能静默恢复风险仓位；完整序列、真实休市和发布前窗口有正控制；另一个 OR 分支确定触发时保留正确结果。现有专属反例为 4 失败、4 通过，四个失败对应同一缺陷的两个数据攻击及两个调用层次。

### F2 / P1：Nasdaq 补缺跨分红统一缩放，真实开盘与账户收益被改写

**位置：**`_merge_same_ticker_gap_prices`（2849–2875），由 `_repair_us_yahoo_internal_gaps_with_nasdaq` 和 `fetch_yahoo` 调用。

函数用整个重叠窗口的“Yahoo复权收盘 / Nasdaq原始收盘”中位数，统一补缺口的开盘与收盘，并允许比例有 1% 波动。小额分红会让复权因子发生阶跃；即使缺口日已有有效复权收盘、可计算该日因子，仍使用全窗中位数。后续 OHLC 检查只确认日期及有限正价，无法拦截尺度错误。

**最小反例：**分红前因子 0.995、分红后因子 1；缺口日原始开收盘均 100、已知复权收盘也是 100，缺失开盘却被补为 **99.5**。`fetch_yahoo` 返回 `Yahoo+Nasdaq-gap`，内部正式行情校验通过。

**原生账户核验：**前晚持有 BIL，下一开盘全部买入 QQQ，当天真实开收盘不变，默认单边费率 0.1%。B7.8、B7.9 两条账户重建路径均得到：

| 同一合成交易 | 正确开盘 100 | 错误开盘 99.5 |
| --- | ---: | ---: |
| 当日净收益 | -0.0999001% | +0.40211045% |

差异为 **50.201055 个基点**。这是单日数学反例，不代表实际历史收益高估幅度。

**修补建议：**同日复权收盘和原始收盘都有效时，用该日因子补开盘；整日缺失且两侧因子不一致时，应取得可验证的逐日复权因子，否则保留缺口并让正式路径中止。不要仅收紧 1% 容差代替正确的逐日因子。记录补缺日期、数据源、使用因子及拒绝原因。

**验收：**覆盖小额分红、拆股、只有开盘缺失、整行缺失、恒定因子正控制；两版账户的收益、费用及成交价都应与正确开盘路径一致。4 个失败反例覆盖行情入口、整行歧义与两版账户；另有恒定因子正控制通过。

### F3 / P2：C 策略借用了 B 的数据日期，已确认目标被标成盘中假设

**位置：**`_handle_live_signal`（13872、13891）、`_handle_live_params`（13941、13961）；C 数据截断逻辑在 13411–13420 附近。

当 B 已有今日盘中行情，而 C 独有标的缺今日报价时，C 可以合法停留在上一已确认收盘日。两个实时处理器却用 B 的日期生成 `us_intraday` 并传给 C。

**生产可达性：**仅令 AVUV 今日行情及实时补充缺失，真实 `_fetch_data` 保留全部校验，返回 B=`2026-09-29`、C=`2026-09-28`。处理器测试进一步证明 C 的昨日已确认调整会被当作盘中假设，信号文案出现“现在不执行，等待收盘确认”。实时信号、实时参数均复现。

**修补建议：**为 B、C 分别保留行情 as-of、是否盘中、信号确认日及计划执行时点；C 面板展示自己的日期。已错过原计划开盘时，应提示核对执行状态，不能简单将旧信号改成“现在立即执行”。同步核验四个查询入口与导出字段。

**验收：**B今日/C昨日、B昨日/C今日、同日盘中、同日收盘、早收市和实时补充失败。现有反例 2 失败、3 通过，包含同日正控制及真实取数可达性。

## 单列的条件性问题

### H1 / P2–P3：直接调用 strict runner 时，非执行日缺失仍被接受

`_validate_subb_price_input`（8145–8156、10167–10178）没有全索引交易日完整性检查，后续只在发生执行时检查相邻交易日。完整合成美股行情删去 2024-09-17，两个 strict runner 仍把 9/16 至 9/18 的变化算作一个日收益。

**范围限制：**默认 `_fetch_data` 已检查原始日历，本轮没有证明默认查询链能绕过。因此这是研究脚本/缓存直接调用入口的防线缺口，不与 F1–F3 混计。建议 strict runner 在入口一次性验证其合同所要求的完整交易日历；保留合法上市前空值和代理阶段规则。两个拒绝测试失败、两个完整日历控制通过。

### H2 / P3：启用 Sub-C 择时后，空仓仍可能收融资利差

`_apply_subc_vol_scaling`（12881–12889）在普通持有日按基础敞口计算融资，没有乘实际择时风险比例；调整日账户却按 `signal::资产` 计算。全现金、价格不变、股票及黄金 scale=1.5 时，合成每日收益为 `-0.00001488095238`，应为 0。

**默认 `PROD_USE_TIMING=False`，当前默认组合不触发。** 建议普通日融资基数和调整日统一使用有效风险敞口；全现金、部分现金及满风险仓分别验证。此项 1 个失败反例、2 个正控制。

## 报表口径问题：查询开头恰逢一地休市

`_handle_performance`（14200–14208）先切查询窗，再由 `_performance_combined_daily_returns`（11169–11178）取各袖首条记录的最大值。若查询从 A股休市、美股开市之日开始，前面的美股收益会被剔除；只有该一天时，Combined 为空。

合成 9/24 各袖收益均0、9/25 美股三袖各+10%、9/28全部0，查询9/25–28只保留28日的0；若按9/25建仓且休市袖记0，则组合应为+7%。前日均0排除了权重漂移的干扰。真实报表处理器的单日查询另验证 XLSX Combined 单元格为 N/A，而按合成输入的上述口径应为-0.027%。

源码一处披露“查询区间共同可用起点建仓”，另一处承诺“真实休市按零收益承接”。因此将本项列为 **P2 报表合同/产品口径问题**，不把“全历史漂移与查询重置不同”本身算作 bug。

建议保留查询起点重置初始权重的定义，同时向组合函数传入未截断历史覆盖信息：已成立的休市袖承接0收益，真实交易日缺行拒绝。若坚持所有市场同开后才建仓，需明确展示组合实际起点、被排除日期及单日不提供组合值的原因。3 个反例用于验证该口径差异，不能据此推断实际历史损失。
