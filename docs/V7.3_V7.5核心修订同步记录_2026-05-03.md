# V7.3 / V7.5 核心修订同步记录（2026-05-03）

本文记录 2026-05-03 对 `mnt_bot V 7.0 plus.py`、`mnt_bot V 7.1 plus.py`、`mnt_bot V 7.2 plus.py`、`mnt_bot V 7.3 plus.py`、`mnt_bot V 7.5 plus.py` 的一次集中修订。此次修订以 `V7.3 plus` 最终状态机为模板，同步旧版本和 V7.5 的核心执行、成本、展示和本地运行兼容层。

## 修订范围

1. `Sub-A`：
   - 引入有效仓位状态机，按上一日实际持仓和实际权重计算收益。
   - 现金部分计入无风险收益，借入部分计入融资成本。
   - 成本按上一日实际仓位到今日目标仓位的有效 turnover 计算。

2. `Sub-A-DK` / `DK`：
   - 同步最终 effective legs 状态机。
   - 所有 DK overlay 之后，再根据最终 pair、方向、weight 拆分 long/short legs。
   - 成本按最终腿部净敞口变化计算，避免 pair 切换、降敞口、恢复敞口、零敞口状态下的重复或无意义成本。
   - 修复零敞口 `none_0 -> none_0` 时 weight 变化仍记录“杠杆调整”的展示问题。

3. `Sub-B`：
   - `run_us_rotation_mix()` 同步 `return_before_execution_cost` / `execution_cost` / `return` 三段式字段。
   - `V7.0` 的旧 `run_us_rotation()` 做等价补丁，避免 VolReg 后续把已扣费 return 当作 gross return。
   - `V7.5` 的 EMA leg 同步 gross/cost 字段。
   - `V7.5` 的 official/EMA blend 改为账户层合并实际权重后，再统一计算 `subb_execution_turnover` 和 `subb_execution_cost`。

4. `Sub-B VolReg`：
   - 同步 effective weight + `CASH` 状态机。
   - VolReg 不再简单把收益置零后再次粗略扣成本，而是生成最终 effective weights，并将 `CASH` 作为非交易资产处理。
   - 信号展示补齐 `volreg_cash_next`、`model_hypo_us_w`、`effective_hypo_us_w`。

5. 资金设置：
   - `V7.0 / V7.1`：资金拆分与 `COMBINED_WEIGHTS = 15 / 10 / 55 / 20` 对齐。
   - `V7.2 / V7.5`：人民币拆分按 `Sub-A:Sub-A-DK = 15:10`，微盘 15% 继续由独立脚本处理，美元默认给 `Sub-B`。
   - 修复 `V7.0 / V7.1` 资金提示中残留的 `Sub-B 40/(40+30), Sub-C 30/(40+30)`。

6. `V7.5` 微盘口径：
   - 采用独立模块口径。
   - 参数页改为“v1.6 target-vol 独立模块”。
   - 明确本 Bot 不参与微盘净值计算；缓存检查由微盘独立脚本负责。

7. Poe 本地兼容层：
   - 将 `V7.3` 的 `_install_poe_native_compat()` 同步到 `V7.0 / V7.1 / V7.2 / V7.5`。
   - 本地或 CI 环境可导入并测试不依赖 `poe.call` 的路径。

8. 回测纪律：
   - `AGENT.md` 补充组合回测刷新铁律、`Sub-A-DK` 指数发布日期约束、测试数据与 outputs 纪律，以及 2026-05-03 V7.3 POE 回测事故复盘。

## 明确没有做的事

1. 本轮代码同步没有发布新的 CAGR、最大回撤、Sharpe 或 PV 绩效数字。
2. 没有把微盘 v1.6 纳入 `V7.5` 主 Bot 的 PV/收益查询。
3. 没有把本地数据缓存修改作为本次云端同步范围。
