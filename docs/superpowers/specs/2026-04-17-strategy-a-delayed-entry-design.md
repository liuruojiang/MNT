# 策略 A 延后入场设计

## 背景

用户要求调整策略 A（`Sub-A`）的买入执行方式：

- 当策略 A 发出买入信号后，不立即入场。
- 仅当目标指数或 ETF 后续第一次出现下跌日时才执行买入。
- 下跌日定义为：当日收盘价小于前一日收盘价，即 `close[t] < close[t-1]`。
- 入场价格使用该下跌日的当日收盘价。
- 卖出逻辑保持不变，仍按当前信号当日执行。

## 当前实现摘要

当前策略 A 逻辑位于主脚本的 `run_cn_strategy(close_df, equity_codes)`：

- 每个交易日计算候选资产的 bias momentum 与 R² 过滤。
- 若 `ideal != holding`，当天直接切仓。
- 当天收益按旧持仓当日收益和交易成本计算。
- 不存在“待入场”“挂单等待”“放弃本次入场”等中间状态。

因此，现有实现不支持“信号先出现，后续等待首次下跌日再买入”。

## 需求定义

### 买入规则

- 仅对 `cash -> 风险资产` 的入场动作增加等待机制。
- 当策略生成正式买入目标时，不立即切仓。
- 记录一个待入场目标，并进入等待状态。
- 从下一交易日起逐日检查该目标。
- 第一次满足 `close[t] < close[t-1]` 时，于该交易日收盘执行买入。

### 卖出规则

- `持仓 -> cash` 保持现状，信号当日执行。
- `持仓 -> 其他风险资产` 保持现状，信号当日执行。

### 等待期规则

- 等待期间组合仍处于现金状态，收益按 `CN_RF_DAILY` 计。
- 等待期间如果策略模型的目标发生变化，则取消本次待入场。
- 取消后不自动切换为等待新目标。
- 只有后续再次出现新的正式买入信号时，才重新进入等待状态。

## 推荐实现方案

采用显式状态机，而不是在现有切仓条件中追加零散判断。

### 新增状态

在策略 A 日循环中维护以下状态：

- `holding`：当前实际持仓。
- `pending_entry_target`：待入场目标，默认 `None`。
- `pending_entry_since`：开始等待的交易日，默认 `None`。
- `pending_entry_active`：是否存在有效待入场状态。

### 状态转换

#### 1. 无持仓且无待入场

- 若当日模型目标为 `cash`，保持现金。
- 若当日模型目标为风险资产，登记待入场，不立即买入。

#### 2. 现金且存在待入场

- 若当前模型目标与待入场目标不同，直接取消本次待入场，继续保持现金。
- 若目标未变，检查该目标当日是否满足 `close[t] < close[t-1]`：
  - 满足：按当日收盘执行买入，清空待入场状态。
  - 不满足：继续等待。

#### 3. 已持仓

- 若模型目标与当前持仓一致，继续持有。
- 若模型目标变为 `cash` 或其他资产，按现有逻辑当日切换，不进入等待。

## 回测与记录影响

### 收益计算

- 等待期间收益必须按现金收益计算，不能错误套用待入场目标的价格变动。
- 真正入场当天才开始持有目标资产。
- 入场当天交易成本沿用现有 `cash -> 风险资产` 单边成本逻辑。

### 调仓记录

`extract_cn_rebalances()` 预计无需重写核心结构，但需要验证以下事实：

- 记录的买入日期应为实际入场日，而非信号首次出现日。
- 记录的买入价格应为实际入场日收盘价。
- 若等待期间发生取消，不应生成虚假成交记录。

### 展示层

信号展示层短期可以先接受“成交日期变化由持仓变化自然反映”的行为。
若后续需要更清晰表达“当前处于等待入场”或“已放弃本次入场”，可以再追加展示字段，但这不是本次逻辑验证的前置条件。

## 测试设计

实现必须遵循测试先行，至少覆盖以下行为：

1. 买入信号出现后，不在信号日入场，而是在首个下跌日入场。
2. 等待期间若始终没有下跌日，则一直保持现金。
3. 等待期间若模型目标改变，则取消本次待入场，且不自动等待新目标。
4. 卖出信号维持当前行为，仍在信号日执行。

## 风险与注意事项

- 若待入场状态实现不严谨，最容易出现的错误是“等待期间已经按目标资产计收益”，这会使回测被污染。
- 若目标变化取消逻辑写错，可能会意外变成“自动等待新目标”，与用户要求不符。
- 若展示层仍把首次信号日误当成成交日，会造成信号说明和实际持仓不一致，因此实现后必须检查调仓提取结果。
